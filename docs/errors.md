# Error Handling

OpenZed Git includes a professional error notification system that provides clear, user-friendly error messages and persists detailed error logs for debugging.

## TUI Error Notifications

When an error occurs, OpenZed Git displays a clean Aura Dark TUI notification instead of raw Rust errors or panic messages.

### Error Notification Format

```
────────────────────────────────────────────────────────
│              OpenZed Git: Error
────────────────────────────────────────────────────────

  ✗ Git command failed

  Command:
  push

  Error type:
  Git Error

  Message:
  No upstream branch found.

  Suggested fix:
  openzed-git push

  Error log saved:
  .openzed-git/gitlogerror.md
```

## Error Types

OpenZed Git classifies errors into the following types:

| Type | Display Name | Description |
|------|-------------|-------------|
| `Internal` | Internal Error | Something went wrong inside OpenZed Git |
| `Git` | Git Error | Git command failed |
| `GitHubCli` | GitHub CLI Error | GitHub CLI (gh) command failed |
| `GitHubAuth` | GitHub Authentication Error | GitHub CLI not authenticated |
| `GitHubApi` | GitHub API Error | GitHub API request failed |
| `Config` | Config Error | Config file parsing/loading failed |
| `FileSystem` | File System Error | File/directory operation failed |
| `Zed` | Zed Integration Error | Zed CLI operation failed |
| `Unknown` | Unknown Error | Unclassified error |

## Error Log File

All errors are logged to a markdown file for debugging:

### Log Location

**Preferred (in project):**
```
.openzed-git/gitlogerror.md
```

**Fallback (if not in Git repo):**
```
~/.config/openzed-git/gitlogerror.md
```

### Log Format

```markdown
# OpenZed Git Error Log

This file is automatically generated by OpenZed Git.

---

## 2026-05-12 20:45:11

| Field | Value |
|---|---|
| Command | `pr-create` |
| Error Type | GitHub Authentication Error |
| Title | GitHub authentication failed |
| Suggested Fix | `gh auth login` |

### Message

```text
GitHub CLI is not authenticated.
```

### Raw Error

```text
gh: To get started with GitHub CLI, run: gh auth login
```

### Context

```text
Current directory: /home/user/project
Git branch: feature/pr-flow
Git state: Clean
```

---

```

### Sharing Logs

When reporting bugs:

1. Find the error log file
2. Copy the relevant error section
3. Include it in your bug report

## Suggested Fixes

OpenZed Git automatically suggests fixes based on error type:

| Error Type | Suggested Fix |
|------------|---------------|
| GitHubCli (not found) | Install GitHub CLI from https://cli.github.com/ |
| GitHubAuth | Run: `gh auth login` |
| GitHubApi | Check internet connection |
| Git (no upstream) | Run: `openzed-git push` |
| Git (merge conflict) | Run: `openzed-git conflicts` |
| Git (rebase conflict) | Run: `openzed-git rebase-helper` |
| Git (not a repo) | Run: `git init` or open a Git folder |
| Config | Run: `openzed-git config` |
| Zed | Install/enable Zed CLI |

## Error Classification

Errors are automatically classified based on:

1. **Error message content** - Keywords like "gh", "git", "auth", "config"
2. **Command context** - Which command was being run
3. **Stack trace patterns** - Recognizable error patterns

## Non-Error Cases

The following are **not** logged as errors:

- User cancellation (pressing Cancel/No)
- Successful operations
- Warnings without failure

## Debugging Tips

If you encounter an error:

1. Note the error type shown in the notification
2. Check the suggested fix
3. Review the error log for full details
4. Run the suggested command to resolve

## Getting Help

If an error persists:

1. Check the troubleshooting guide: `docs/troubleshooting.md`
2. Run `openzed-git doctor` to check setup
3. Share the error log section when reporting issues
